# vtoall - from VAL to 05-09llm
Date: 2026-09-28. Backend reference for the frontend. Backend agents 00-04 are finished; backend code is frozen. Describes what the code in `abc-bank_val.zip` actually does (design v1.0 + `AMENDMENTS.md`). Where it differs from the design, the code wins here. Validated by VAL on real MySQL 8.0.46 (selfchecks green, integrity `ok:true`); frontend and `tests/` were not validated.

## 1. Basics
- Base `http://127.0.0.1:5000/api`; JSON in/out; upload = multipart. Login = `X-User-Id: <int>` header on every call except `auth/*` and `system/*` (no auth). Missing/non-numeric/unknown/system user -> 401 `AUTH_REQUIRED`.
- Envelope: `{success:true,data:{...}}` or `{success:false,error:{code,message,details:{}}}`. `details` is always an object; field errors = `details.fields {field: reason}`.
- Money: responses = string with 2 decimals. Requests = JSON number or string, <= 2 decimals, digits only (no sign, no exponent, "" rejected); send strings. Never do float math.
- Time `2026-09-28T10:15:30Z` (UTC); dates `YYYY-MM-DD`.
- Pagination (`page` default 1, `page_size` default 10, > 50 clamped to 50, non-numeric or < 1 -> 400): `data = {items, page, page_size, total_items, total_pages}` (+ `unread_count` on notifications).
- Unknown `/api/*` path -> 404 `NOT_FOUND`; wrong verb -> 405 `METHOD_NOT_ALLOWED`; malformed JSON -> 400 `VALIDATION_ERROR`. Trailing slash optional. Send JSON objects only.
- Seed: system account id 1 `000000000001` (never visible to users). `alice/alice123` acct 2 `100000000001` 10000.00 · `bob/bob123` acct 3 `100000000002` 5000.00 · `carol/carol123` acct 4 `100000000003` 25000.00.

## 2. Error codes (HTTP)
400 `VALIDATION_ERROR` · 401 `AUTH_REQUIRED`, `INVALID_CREDENTIALS` · 403 `FORBIDDEN` · 404 `NOT_FOUND`, `ACCOUNT_NOT_FOUND` · 405 `METHOD_NOT_ALLOWED` · 409 `USERNAME_TAKEN`, `EMAIL_TAKEN`, `INVALID_STATE` · 422 `INSUFFICIENT_FUNDS`, `ACCOUNT_NOT_ACTIVE`, `SAME_ACCOUNT_TRANSFER`, `LIMIT_EXCEEDED`, `TXN_NOT_REVERSIBLE`, `REVERSAL_FUNDS_UNAVAILABLE`, `LOAN_INCOMPLETE` · 500 `INTERNAL_ERROR` · 503 `SIMULATED_NETWORK_FAILURE`, `TXN_RETRY_EXHAUSTED` · 504 `NETWORK_TIMEOUT`.
- `INSUFFICIENT_FUNDS` details `{available, required}` (money strings). `LOAN_INCOMPLETE` details `{missing:[...]}`. `NETWORK_TIMEOUT` details `{hint}`. `REVERSAL_FUNDS_UNAVAILABLE` details `{}`.
- `LIMIT_EXCEEDED` only = 6th open account. Money min/max violations are 400 `VALIDATION_ERROR`.

## 3. Auth, users, accounts
- `POST /auth/register` {username 3-30 `[A-Za-z0-9_]`, password >= 4, full_name, email, phone 10-15 digits, address?, date_of_birth? YYYY-MM-DD} -> **201** `{user, account}` (one SAVINGS account, 0.00). Errors: 400 (all bad fields at once), `USERNAME_TAKEN`, `EMAIL_TAKEN`.
- `POST /auth/login` {username, password} -> 200 `{user, accounts:[Account]}`. Wrong/blank/unknown/system -> 401 `INVALID_CREDENTIALS` (never `AUTH_REQUIRED`).
- `GET /users/me` -> `{user}`. `PUT /users/me` any of full_name/email/phone/address/date_of_birth (blank address/dob clears) -> `{user}`; `EMAIL_TAKEN`.
- `GET /accounts` -> `{accounts:[Account]}` (all statuses, by id).
- `POST /accounts` {account_type: `SAVINGS`|`CURRENT`} **required** -> **201** `{account}`; 6th non-closed -> 422 `LIMIT_EXCEEDED`.
- `GET /accounts/lookup?account_number=` (12 digits) -> `{account_number, holder_name (masked "Bob S."), status}`; unknown or system number -> 404 `ACCOUNT_NOT_FOUND`; bad format -> 400.
- `GET /accounts/{account_id}` -> `{account}`; unknown 404 `NOT_FOUND`; not yours 403 `FORBIDDEN` (e.g. id 1).
- `PATCH /accounts/{id}/status` {status: ACTIVE|FROZEN|CLOSED} -> `{account}`. Same status = 200 no-op. CLOSED is terminal; closing needs balance 0.00, no PENDING_REVIEW/APPROVED/ACTIVE loan on it, and another non-closed account; else 409 `INVALID_STATE` (message explains). Frozen/closed accounts fail money moves with `ACCOUNT_NOT_ACTIVE`.
- Account = `{account_id, account_number, account_type, balance, status, created_at}`; User = `{user_id, username, full_name, email, phone, address, date_of_birth, created_at}`.

## 4. Money movement
Shared body fields: `note` <= 100, `idempotency_key` 8-64 `[A-Za-z0-9_-]`, `simulate_failure` in `NONE|BEFORE_DEBIT|AFTER_DEBIT|BEFORE_COMMIT|DROP_RESPONSE|RANDOM` (overrides the global mode; invalid -> 400). Body must be a JSON object. Validation errors can arrive in two rounds (account/note/key/mode fields first, then amount).
- `POST /transactions/transfer` {from_account_number, to_account_number, amount 1.00-200000.00, note?, idempotency_key?, simulate_failure?} -> **201** new / **200** replay: `{transaction, from_account:{account_number,balance}, idempotent_replay}`. Sender unknown -> 404 `ACCOUNT_NOT_FOUND`; sender not yours -> 403; recipient unknown -> 404 `ACCOUNT_NOT_FOUND`; `SAME_ACCOUNT_TRANSFER`, `ACCOUNT_NOT_ACTIVE`, `INSUFFICIENT_FUNDS` (422).
- `POST /transactions/deposit` {account_number (yours), amount 1.00-100000.00, note?, idempotency_key?, simulate_failure?} -> 201/200 `{transaction, account:{account_number,balance}, idempotent_replay}`.
- `POST /transactions/{txn_ref}/reverse` {idempotency_key?, simulate_failure?} (`{}` ok) -> 201/200 `{transaction (REVERSAL), original (status REVERSED), idempotent_replay}`. Rules: original must be a COMPLETED TRANSFER <= 24 h old, requester = sender. Check order: unknown 404 `NOT_FOUND` -> not a party 403 -> not reversible 422 `TXN_NOT_REVERSIBLE` -> party but not sender 403 -> recipient short of funds 422 `REVERSAL_FUNDS_UNAVAILABLE`.
- `GET /transactions?account_id=&type=&status=&from_date=&to_date=&page=&page_size=` newest first. `type` TRANSFER|DEPOSIT|LOAN_DISBURSEMENT|LOAN_REPAYMENT|REVERSAL; `status` COMPLETED|FAILED|REVERSED. `account_id` must be yours (else 403; bad format 400). Dates YYYY-MM-DD, `to_date` inclusive, bad -> 400. Includes FAILED rows. Visible if either side is your account.
- `GET /transactions/{txn_ref}` -> `{transaction, ledger_entries:[{account_number, entry_type DEBIT|CREDIT, amount, balance_after}]}`; 404 / 403.
- Transaction = `{txn_ref, txn_type, status, amount, from_account_number, from_name, to_account_number, to_name, description, direction IN|OUT|null, failure_code, failure_reason, related_txn_ref, loan_id, created_at, completed_at}`. System side is name "ABC Bank"; others masked. `direction` is relative to the viewer, or to `account_id` when filtered.
- **Idempotency:** same key + same user replays the original (200, `idempotent_replay:true`, nothing changes) even if the body differs. A key used by another user -> 400 `VALIDATION_ERROR` (`idempotency_key`). FAILED rows store no key, so retrying a failed request with the same key is safe. Generate one key per form submission; reuse it for retries; new key after success or after any edit.
- **Failure handling for the UI:**
  - 503 `SIMULATED_NETWORK_FAILURE`: fully rolled back, money safe; offer Retry with the same key.
  - 504 `NETWORK_TIMEOUT` (with `details.hint`, no `txn_ref`): money DID move. Retry with the same key -> 200 replay (a replay never re-fires DROP_RESPONSE). Retry <= 3 x, 1 s apart.
  - 503 `TXN_RETRY_EXHAUSTED`: contention; retry with the same key.
- **FAILED history rows** are created for every failed money attempt once the sender/loan is known, except `VALIDATION_ERROR`, `AUTH_REQUIRED`, `FORBIDDEN`, `NOT_FOUND`, unknown sender. So they appear for: unknown recipient (`to_account_number:null`, `to_name:null`), `INSUFFICIENT_FUNDS`, `SAME_ACCOUNT_TRANSFER`, `ACCOUNT_NOT_ACTIVE`, the simulated 503, `TXN_RETRY_EXHAUSTED`, `TXN_NOT_REVERSIBLE`, `REVERSAL_FUNDS_UNAVAILABLE`, and unexpected `INTERNAL_ERROR`. Not for 504. Failed transfers also create a `TRANSFER_FAILED` notification (transfers only). Show `failure_code`; do not rely on `failure_reason` text.

## 5. Loans (personal only)
Status flow: `DRAFT -> PENDING_REVIEW -> APPROVED -> ACTIVE -> CLOSED`; `REJECTED` from review; `CANCELLED` from DRAFT/PENDING_REVIEW/APPROVED. Wrong state -> 409 `INVALID_STATE`. Edit endpoints (details, income-details, documents, guarantor) and `submit` = DRAFT only; `review` = PENDING_REVIEW only; `accept` = APPROVED only; `repay` = ACTIVE only. Every `{loan_id}` route: unknown 404, not yours 403 (checked before validation). Loan validation errors list all bad fields at once.
- `GET /loans/config` -> types (only PERSONAL enabled), `min_amount 5000.00`, `max_amount 500000.00`, `tenure_options [6,12,18,24,36]`, `base_rate`, `best_rate`, `employment_types`, `relationships`, `document_types`, `max_upload_bytes 2097152`, `allowed_mime_types`.
- `GET /loans/estimate?amount=&tenure_months=&rate=` (rate optional, default 9.00, 0.00-50.00) -> `{amount, tenure_months, annual_rate, emi_amount, total_interest, total_payable}`. 50000/12/9.00 -> emi 4372.57, interest 2470.90, payable 52470.90 (last EMI absorbs rounding; do not compute EMI x n).
- `POST /loans` {loan_type "PERSONAL", account_number (yours, ACTIVE)} -> **201** `{loan}` (DRAFT, `current_step 2`). Errors: 400, `ACCOUNT_NOT_FOUND`, 403, `ACCOUNT_NOT_ACTIVE`.
- `GET /loans?status=` -> `{loans:[LoanSummary]}` newest first; unknown status 400. LoanSummary = `{loan_id, loan_type, status, requested_amount, approved_amount, interest_rate, emi_amount, tenure_months, installments_paid, installments_total, next_due_date, created_at}`.
- `GET /loans/{id}` -> `{loan}`.
- `PUT /loans/{id}/details` all required: full_name <= 100, phone 10-15 digits, address <= 255, date_of_birth YYYY-MM-DD (age >= 21), requested_amount 5000-500000, tenure_months in options -> 200 `{loan}`.
- `PUT /loans/{id}/income-details` {pan_number `AAAAA9999A`, aadhar_number 12 digits, employment_type, monthly_income 0.01-1,000,000,000} -> 200 `{loan}`.
- `POST /loans/{id}/documents` multipart `document_type` (INCOME_PROOF|PAN_CARD|AADHAR_CARD), `file` (pdf/png/jpeg, non-empty, <= 2 MB) -> **201** `{document, loan}`. Same type again replaces the old file.
- `PUT /loans/{id}/guarantor` {guarantor_name, guarantor_aadhar 12 digits, guarantor_phone?, relationship} -> 200 `{loan}` (upsert).
- `POST /loans/{id}/submit` -> 200 `{loan}` PENDING_REVIEW. Missing parts -> 422 `LOAN_INCOMPLETE`, `details.missing` items: `details`, `income_details`, `documents:INCOME_PROOF|PAN_CARD|AADHAR_CARD`, `guarantor`.
- `POST /loans/{id}/review` {decision AUTO|APPROVE|REJECT, remarks? <= 255} -> **200** `{loan}` with status APPROVED or REJECTED (a rejection is NOT an error). Fills `interest_rate, emi_amount, total_interest, total_payable, approved_amount (approved only), review`. AUTO can reject with `review.rejection_codes` (array; all failing rules): `LOW_INCOME` (income < 10000), `EMI_TOO_HIGH` (EMI at 9% / income > 0.50), `AMOUNT_EXCEEDS_LIMIT` (amount > 20 x income; always appears together with `EMI_TOO_HIGH`), `TOO_MANY_ACTIVE_LOANS` (>= 2 ACTIVE), `GUARANTOR_SAME_AS_APPLICANT`. `APPROVE` overrides all rules; `REJECT` -> `["MANUAL_REJECTION"]`. Rate = max(5.00, 9.00 - income - guarantor - tenure - loyalty discounts); `review.rate_breakdown` = `{base, income_discount, guarantor_discount, tenure_discount, loyalty_discount, final_rate}` (strings). Example: income 60000, 50000, 12 m, PARENT -> 5.00.
- `POST /loans/{id}/accept` {idempotency_key?} -> **200** `{loan (ACTIVE), transaction (LOAN_DISBURSEMENT), schedule:[Installment]}` (no `idempotent_replay` field; a replay is also 200). First due date = today + 1 month. Body `simulate_failure` is ignored here (only the global mode applies). Failures: 503/504 as in section 4; loan stays APPROVED on 503.
- `POST /loans/{id}/cancel` -> 200 `{loan}`.
- `GET /loans/{id}/schedule` -> `{loan_id, schedule:[Installment], summary:{paid_count, total_count, outstanding_principal, total_paid, total_remaining}}` (no schedule yet: `[]`, zeros, "0.00").
- `POST /loans/{id}/repay` {account_number? (default = loan's account; must be yours), idempotency_key?, simulate_failure?} -> **201** new / **200** replay `{installment, transaction (LOAN_REPAYMENT), loan, idempotent_replay}`. Pays the lowest PENDING installment in full; last one -> loan CLOSED. `INSUFFICIENT_FUNDS` (installment stays PENDING), `ACCOUNT_NOT_ACTIVE`, 403, `ACCOUNT_NOT_FOUND`. Here `simulate_failure` is honoured but not validated.
- Installment = `{installment_no, due_date, emi_amount, principal_component, interest_component, balance_after, status PENDING|PAID, is_overdue, paid_at}`.
- Loan = `{loan_id, loan_type, status, current_step, account_number, requested_amount, tenure_months, approved_amount, interest_rate, emi_amount, total_interest, total_payable, personal_details|null, income_details|null, documents:[{document_type, original_filename, uploaded_at}], guarantor|null, review:{mode, remarks, rejection_codes, rate_breakdown, reviewed_at}, installments_paid, installments_total, submitted_at, disbursed_at, closed_at, created_at}`. `installments_total` = tenure once ACTIVE/CLOSED, else 0.
- `current_step` (derived): 5 when status != DRAFT; else 2 until details saved; 3 until income details saved and all 3 documents uploaded; 4 once those are done (the guarantor does not move it; submit still requires it).
- Loan failure rows: a FAILED history row (with `loan_id`) is written for accept/repay failures after the money attempt started, not for `INVALID_STATE`/validation.

## 6. Notifications, dashboard, system
- `GET /notifications?unread_only=&page=&page_size=` (unread_only true|1|yes) -> paginated + `unread_count`. `POST /notifications/{id}/read` -> `{notification}` (404/403). `POST /notifications/read-all` -> `{updated: n}`. Notification = `{notification_id, type, title, message, related_ref, is_read, created_at}`. Types: TRANSFER_SENT, TRANSFER_RECEIVED, TRANSFER_FAILED, TRANSFER_REVERSED, DEPOSIT, LOAN_SUBMITTED, LOAN_APPROVED, LOAN_REJECTED, LOAN_DISBURSED, REPAYMENT_PAID, LOAN_CLOSED.
- `GET /dashboard` -> `{user:{user_id,full_name}, primary_account:{account_id,account_number,balance}|null, total_balance, recent_transactions:[5 Transaction], unread_notifications, active_loans, next_installment:{loan_id,installment_no,due_date,emi_amount}|null, promo:{headline,subtext}, system_health:{status,db,simulation_mode,failed_txns_24h}}`.
- `GET /system/health` (no auth) -> `{status ALL_GOOD|DEGRADED, db UP|DOWN, server_time}`. `GET /dashboard` no longer includes `system_health`.
- `GET /system/integrity` (no auth) -> `{ok, checks:{I1..I6:{ok, violations:[]}}}`.
- **Staff API (`X-User-Id` of an OFFICER; customers get 403, `POST /auth/login` now returns `user.role`)**: `GET /admin/overview` (health incl. `simulation_mode`, counts) · `GET /admin/integrity` · `GET|PUT /admin/simulation` (as the old `/system/simulation`, plus `tools_enabled`) · `POST /admin/reset` (restores the starting data: `demo` + `officer`) · `GET /admin/customers` · `GET /admin/transactions?status=` · `GET /admin/loans?status=` · `GET /admin/loans/{id}` · `POST /admin/loans/{id}/review` {decision AUTO|APPROVE|REJECT, remarks?}. `PUT /admin/simulation` and `POST /admin/reset` return 403 when `DEBUG_TOOLS=0`. `/system/simulation`, `/system/reset`, `/system/integrity` and `POST /loans/{id}/review` were removed.
- Global simulation mode applies to all money endpoints (transfer, deposit, reverse, accept, repay) unless a per-request `simulate_failure` overrides it (not on accept). `RANDOM` picks one of the 4 fault points with the global probability, else behaves as NONE.
